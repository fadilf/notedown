### Opt-in silence performance profiling

`SilencePerformanceTest` is skipped during ordinary instrumentation runs. For an explicit live benchmark, install the debug app and test APK, then stage `input.m4a` and a runtime-only `key` file in the target app's private `files/silence-profile/` directory using `adb shell run-as com.notedown`. Transfer the key through standard input, never a command-line argument. The test deletes that file, temporarily stores the credential using Android Keystore, and restores the previous credential afterward.

```sh
adb shell am instrument -w -r \
  -e class com.notedown.SilencePerformanceTest \
  -e profileSilence true -e repetitions 3 \
  -e transport chat -e model google/gemini-2.5-flash-lite \
  com.notedown.test/androidx.test.runner.AndroidJUnitRunner
```

The benchmark runs three local decode/Silero passes, then alternating-order live pairs through the production `TranscriptionService` preparation path. `transport chat` uses a test-only audio Chat Completions adapter; omit it to exercise the production multipart `/audio/transcriptions` endpoint. These are different transports: adapter success does not establish that the app's production endpoint works. On November 11, 2026, the production endpoint returned HTTP 400 with `mistralai/voxtral-small-24b-2507`.

Timings, prepared audio sizes/durations, transcript character counts, full provider usage, and exact reported costs are saved to private `files/silence-profile/results.json`; no transcripts or keys are written to results. API time includes encoding, upload, provider processing, download, parsing, and final temporary-file deletion. Total time excludes capture, queue scheduling, database persistence, cleanup, and editor insertion. Set `repetitions` to `0` for local-only profiling. Remove the private profiling directory and host-side input copies afterward. Emulator timings are not physical-device performance measurements.

For a duration-billed STT comparison, use `-e model moondream/parakeet-ultra` and omit `-e transport chat`. This model supports the production multipart endpoint; its usage can report `seconds` and `cost` without token counts. The earlier Voxtral HTTP 400 does not establish that the transcription endpoint is generally unsupported. Use a dedicated emulator if other test sessions install or uninstall the app concurrently, and select it explicitly with `adb -s SERIAL`.

### Multi-recording optimization lab

`SilenceOptimizationLabTest` is opt-in and uses private runtime inputs, never packaged recording fixtures. `LegacyWavConverter` freezes the pre-optimization decoder. The lab compares the baseline against buffered/in-memory trimming, pooled float conversion, reusable ONNX sessions/tensors, 64/96 ms detection frames, synchronous fused decoding/detection, and overlapping decoding/detection. Experimental reusable-session/full-file-memory implementations live only in `androidTest`; production uses a fresh detector per request, a bounded eight-chunk queue, and 15 lookbehind frames.

After installing the debug and instrumentation APKs on a dedicated device:

```sh
python3 tools/profile_silence.py stage --serial emulator-5556
python3 tools/profile_silence.py local --serial emulator-5556 --repetitions 3
python3 tools/profile_silence.py live --serial emulator-5556 --budget-usd 5
python3 tools/profile_silence.py collect --serial emulator-5556
python3 tools/profile_silence.py report --serial emulator-5556
```

The driver defaults to ignored `test-recordings/` inputs and saves metadata to ignored `.gradle/silence-lab/`. `stage --recordings DIRECTORY` also accepts M4A; `containers` differentially tests those against the legacy decoder/trimmer. `local` rotates variant order and measures complete preparation, including fallback copies when needed. Each output is hashed; unchanged-frame-size variants must match the original trimmed WAV byte-for-byte. Reusable-session timings are warm and exclude the one-time model initialization, which is reported separately. Experimental in-memory variants use more memory than the production streaming implementation.

`live` explicitly spends credits using the local `.env` OpenRouter test key, transferred through standard input and removed from staging afterward. Byte-identical variants reuse the same response in memory instead of making duplicate paid requests (`request_sent: false` and `api_ms: 0` are reused results, not latency measurements). Only usage, timing, word counts, and normalized word-edit counts are saved. Untrimmed provider output is a consistency reference, not a human-verified transcript; edit counts are not ground-truth transcription accuracy.

The private persistent `budget.json` reserves more than five times the published Parakeet per-second price plus one cent before every paid request, reconciles exact reported costs, and stops after 100 requests or the $5 ceiling. Unknown costs retain their reservation. There are no HTTP retries. Existing paid result ledgers block accidental re-execution. `--input-prefix stress_ --session quiet-results` selects separately staged stress inputs while retaining the same cumulative budget. `e2e` runs original/legacy-trimmed/production-trimmed requests in rotating order, three repetitions each on four representative recordings from this experiment; it shares the same budget and requires those inputs. Its totals exclude capture, scheduling, persistence, cleanup-model requests, and editor insertion.

On November 14, 2026, the Android 15 x86_64 debug-emulator experiment covered 13 supplied MP3s (328.17 container seconds), five synthetic stress cases (-12 dB, -24 dB, alternating levels, silence, and tone), and 486 timed preparation runs in the final nine-variant pass. Production output matched the baseline on every case. On the 13 originals, the sum of per-recording median preparation times fell from 5.602 s to 3.610 s (35.5%); the warm-session/in-memory overlapping prototype reached 3.104 s. On two approximately one-minute recordings, median live preparation-to-response time fell from 1.937 s to 1.542 s and from 2.364 s to 1.897 s. A short recording regressed in total live latency despite faster preparation, illustrating API noise and fixed overhead. The 92 successful paid requests reported $0.03961259557282181123 in total costs.

All 13 recordings were additionally re-encoded as 44.1 kHz mono AAC/M4A at the app's 96 kbps rate. The 39 paired compatibility checks (three per file) confirmed byte-identical decoded and trimmed WAVs between legacy and production implementations. The sum of per-file median preparation times was 6.353 s legacy versus 4.587 s optimized (27.8% lower). These compatibility checks ran legacy then optimized in each pair; the main MP3 experiment rotated variant order.

Also verify cancellation while the bounded queue is active, malformed audio, concurrent independent sessions, original/WAV no-speech fallbacks, and temporary-file deletion. `StreamingSilenceWriterTest` differentially tests arbitrary chunk boundaries, padding overlap, no/continuous speech, and partial final frames. After collecting metadata, `python3 tools/profile_silence.py clean --serial SERIAL` removes staged device audio and the lab's generated host AAC/stress directories, retaining metadata. Keep the original local recordings private and untracked.
