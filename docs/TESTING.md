### Opt-in silence performance profiling

`SilencePerformanceTest` is skipped during ordinary instrumentation runs. For an explicit live benchmark, install the debug app and test APK, then stage `input.m4a` and a runtime-only `key` file in the target app's private `files/silence-profile/` directory using `adb shell run-as com.notedown`. Transfer the key through standard input, never a command-line argument. The test deletes that file, temporarily stores the credential using Android Keystore, and restores the previous credential afterward.

```sh
adb shell am instrument -w -r \
  -e class com.notedown.SilencePerformanceTest \
  -e profileSilence true -e repetitions 3 \
  -e transport chat -e model google/gemini-2.5-flash-lite \
  com.notedown.test/androidx.test.runner.AndroidJUnitRunner
```

The benchmark runs three local decode/Silero passes, then alternating-order live pairs through the production `TranscriptionService` preparation path. `transport chat` uses a test-only audio Chat Completions adapter; omit it to exercise the production multipart `/audio/transcriptions` endpoint. These are different transports: adapter success does not establish that the app's production endpoint works. On November 11, 2026, the production endpoint returned HTTP 400 with `mistralai/voxtral-small-24b-2507`.

Timings, prepared audio sizes/durations, transcript character counts, full provider usage, and exact reported costs are saved to private `files/silence-profile/results.json`; no transcripts or keys are written to results. API time includes encoding, upload, provider processing, download, parsing, and final temporary-file deletion. Total time excludes capture, queue scheduling, database persistence, cleanup, and editor insertion. Set `repetitions` to `0` for local-only profiling. Remove the private profiling directory and host-side input copies afterward. Emulator timings are not physical-device performance measurements.

For a duration-billed STT comparison, use `-e model moondream/parakeet-ultra` and omit `-e transport chat`. This model supports the production multipart endpoint; its usage can report `seconds` and `cost` without token counts. The earlier Voxtral HTTP 400 does not establish that the transcription endpoint is generally unsupported. Use a dedicated emulator if other test sessions install or uninstall the app concurrently, and select it explicitly with `adb -s SERIAL`.

### Multi-recording optimization lab

`SilenceOptimizationLabTest` is opt-in and uses private runtime inputs, never packaged recording fixtures. `LegacyWavConverter` freezes the pre-optimization decoder. The lab compares the baseline against buffered/in-memory trimming, pooled float conversion, reusable ONNX sessions/tensors, 64/96 ms detection frames, synchronous fused decoding/detection, and overlapping decoding/detection. Experimental reusable-session/full-file-memory implementations live only in `androidTest`; production uses a fresh detector per request, a bounded eight-chunk queue, and 15 lookbehind frames.

After installing the debug and instrumentation APKs on a dedicated device:

```sh
python3 tools/profile_silence.py stage --serial emulator-5556
python3 tools/profile_silence.py local --serial emulator-5556 --repetitions 3
python3 tools/profile_silence.py live --serial emulator-5556 --budget-usd 5
python3 tools/profile_silence.py collect --serial emulator-5556
python3 tools/profile_silence.py report --serial emulator-5556
```

The driver defaults to ignored `test-recordings/` inputs and saves metadata to ignored `.gradle/silence-lab/`. `stage --recordings DIRECTORY` also accepts M4A; `containers` differentially tests those against the legacy decoder/trimmer. `local` rotates variant order and measures complete preparation, including fallback copies when needed. Each output is hashed; unchanged-frame-size variants must match the original trimmed WAV byte-for-byte. Reusable-session timings are warm and exclude the one-time model initialization, which is reported separately. Experimental in-memory variants use more memory than the production streaming implementation.

`live` explicitly spends credits using the local `.env` OpenRouter test key, transferred through standard input and removed from staging afterward. Byte-identical variants reuse the same response in memory instead of making duplicate paid requests (`request_sent: false` and `api_ms: 0` are reused results, not latency measurements). Only usage, timing, word counts, and normalized word-edit counts are saved. Untrimmed provider output is a consistency reference, not a human-verified transcript; edit counts are not ground-truth transcription accuracy.

The private persistent `budget.json` reserves more than five times the published Parakeet per-second price plus one cent before every paid request, reconciles exact reported costs, and stops after 100 requests or the $5 ceiling. Unknown costs retain their reservation. There are no HTTP retries. Existing paid result ledgers block accidental re-execution. `--input-prefix stress_ --session quiet-results` selects separately staged stress inputs while retaining the same cumulative budget. `e2e` runs original/legacy-trimmed/production-trimmed requests in rotating order, three repetitions each on four representative recordings from this experiment; it shares the same budget and requires those inputs. Its totals exclude capture, scheduling, persistence, cleanup-model requests, and editor insertion.

On November 14, 2026, the Android 15 x86_64 debug-emulator experiment covered 13 supplied MP3s (328.17 container seconds), five synthetic stress cases (-12 dB, -24 dB, alternating levels, silence, and tone), and 486 timed preparation runs in the final nine-variant pass. Production output matched the baseline on every case. On the 13 originals, the sum of per-recording median preparation times fell from 5.602 s to 3.610 s (35.5%); the warm-session/in-memory overlapping prototype reached 3.104 s. On two approximately one-minute recordings, median live preparation-to-response time fell from 1.937 s to 1.542 s and from 2.364 s to 1.897 s. A short recording regressed in total live latency despite faster preparation, illustrating API noise and fixed overhead. The 92 successful paid requests reported $0.03961259557282181123 in total costs.

All 13 recordings were additionally re-encoded as 44.1 kHz mono AAC/M4A at the app's 96 kbps rate. The 39 paired compatibility checks (three per file) confirmed byte-identical decoded and trimmed WAVs between legacy and production implementations. The sum of per-file median preparation times was 6.353 s legacy versus 4.587 s optimized (27.8% lower). These compatibility checks ran legacy then optimized in each pair; the main MP3 experiment rotated variant order.

Also verify cancellation while the bounded queue is active, malformed audio, concurrent independent sessions, original/WAV no-speech fallbacks, and temporary-file deletion. `StreamingSilenceWriterTest` differentially tests arbitrary chunk boundaries, padding overlap, no/continuous speech, and partial final frames. After collecting metadata, `python3 tools/profile_silence.py clean --serial SERIAL` removes staged device audio and the lab's generated host AAC/stress directories, retaining metadata. Keep the original local recordings private and untracked.

### WAV versus compressed uploads

`AudioCompressionLabTest` compares the current trimmed 16 kHz mono PCM WAV with AAC-LC/M4A and MP3, each at 32 and 64 kbps. AAC uses Android MediaCodec/MediaMuxer. MP3 uses test-only LAME 3.100, quality 5, compiled with NDK 27.1.12297006 for x86_64. The source archive SHA-256 is pinned in `tools/build_codec_lab_mp3.py` and matches Debian's 3.100 source manifest. The optional JNI library is packaged only in the instrumentation APK, never the application.

```sh
python3 tools/build_codec_lab_mp3.py
./gradlew --no-watch-fs :app:assembleDebug :app:assembleDebugAndroidTest \
  -PcodecLabJniDir="$PWD/.gradle/codec-lab-native/jni"
adb -s emulator-5556 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5556 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
python3 tools/profile_audio_compression.py stage --serial emulator-5556
python3 tools/profile_audio_compression.py prepare --serial emulator-5556 --session codec-run
python3 tools/profile_audio_compression.py live --serial emulator-5556 --session codec-run
python3 tools/profile_audio_compression.py collect --serial emulator-5556 --session codec-run
python3 tools/profile_audio_compression.py report --serial emulator-5556 --session codec-run
```

Use a dedicated API 35 x86_64 emulator with the original `test-recordings/` corpus and local OpenRouter test key. The driver adds three private 20-second attenuation/variable-level stress inputs. `prepare` runs three encoding trials for all five formats on each of 16 recordings, and decodes compressed outputs to reject malformed files or unexpected duration changes before API usage. The historical AAC helper padded a partial final 1024-sample PCM frame and checked duration; production AAC/64 additionally flushes delayed encoder audio and tests that an ending-only sound remains audible (see below). MP3 at 32 kbps can retain encoder delay/padding in decoded duration. Duration-based charges can therefore differ slightly even for the same source speech.

`live` runs one quality comparison per format/file, with three rotating-order repetitions on four representative recordings. Those four also run at a 1,000,000 bit/s file-body upload limit. This application-level pacing simulates an uplink constraint, not cellular latency, packet loss, or a physical-device network. All requests freshly prepare audio through production decoding/trimming, then encode, then call the production multipart transcription endpoint. Recordings where nothing was removed still use the decoded WAV as the experimental reference; an eventual app integration should keep its existing original-compressed fallback instead of needlessly recompressing it. Total time includes preparation, encoding, request construction, upload, processing, response parsing, and ordinary scheduling; final temporary-file deletion is outside the recorded total. Client upload spans include socket buffering. Unrestricted API time also includes variable routing/provider processing and must not be treated as pure transfer time.

The driver imports the highest saved reservation from the preceding silence lab or codec lab into the private persistent credit ledger; it does not overwrite an existing device ledger. Before every request it reserves more than five times the published duration price plus one cent, honors the same cumulative $5 ceiling, and caps the cumulative request count at 500. It never retries failed requests. Session-specific result files prevent accidental paid replay. Each response's usage is recorded exactly; unknown costs retain the reservation. Transcripts remain in memory only. Normalized word-edit differences use the same trimmed WAV's transcription as a consistency reference, not human-verified ground truth.

Results are private metadata under `.gradle/codec-lab/`. The initial run's AAC dropped partial final frames and is retained for audit only. Use `local-results-tail-safe.json`, `live-results-tail-safe.json`, and `summary-tail-safe.json` for the corrected comparison. The corrected run completed 240 local encoding measurements and 180 successful live requests across 16 files. For the original 64-second recording (35.04 seconds after trimming), median total time was WAV 1.427 s, AAC/32 1.208 s, AAC/64 1.229 s, MP3/32 1.136 s, and MP3/64 1.187 s on the unrestricted connection; with the 1 Mbps limit those were 10.452 s, 2.530 s, 3.631 s, 3.239 s, and 4.642 s. Unrestricted rankings varied substantially on another long recording between runs. Across 461 reference words, corrected AAC/32, AAC/64, MP3/32, and MP3/64 had respectively 11, 5, 5, and 6 word edits relative to WAV. These are agreement counts, not measured error rates against true speech.

These historical `tail-safe` results corrected partial-frame truncation, but duration checks alone did not prove preservation of the encoder's delayed ending audio. Production integration subsequently added the audible-ending regression check and explicit encoder-delay flushing described below. The benchmark's AAC/64 helper now delegates to that production encoder; older result files remain unchanged.

Including both initial and corrected codec batches, codec testing reported $0.140795485757075 in 360 requests. Including the preceding silence tests, the cumulative ledger reported $0.18040808132989681123 in 452 requests. At that point, compressed uploads were still experimental. After collecting results, `python3 tools/profile_audio_compression.py clean --serial SERIAL` removes staged/generated audio while retaining metadata and originals.

### Original compressed recording versus shortened compressed recording

The direct comparison uses `stage-recordings` to create app-format stand-ins from the supplied MP3 corpus and three stress cases: mono AAC/M4A at 44.1 kHz, target 96 kbps. This fixture conversion occurs before timing. Both request paths then start from the exact same M4A file. These are file-based emulator experiments, not newly captured microphone recordings or physical-device measurements.

After building/installing the optional MP3-enabled instrumentation APK as above:

```sh
python3 tools/profile_audio_compression.py stage-recordings --serial emulator-5556 --session original-vs-trimmed
python3 tools/profile_audio_compression.py prepare-recordings --serial emulator-5556 --session original-vs-trimmed
python3 tools/profile_audio_compression.py compare-recordings --serial emulator-5556 --session original-vs-trimmed
python3 tools/profile_audio_compression.py collect --serial emulator-5556 --session original-vs-trimmed
python3 tools/profile_audio_compression.py report-recordings --serial emulator-5556 --session original-vs-trimmed
```

The three paths are original M4A uploaded directly; production decoding/silence trimming plus AAC/64 encoding; and production decoding/silence trimming plus MP3/32 encoding. When trimming returns false, both shortened paths upload the original M4A without re-encoding, preserving the real fallback behavior. Local preflight validates candidate encodings before paid requests. Each of the 16 fixtures runs all six permutations of request order, so each path appears first and last twice. Four fixtures also run those six orders with a 1 Mbps file-body upload limit, for 360 paid requests total. A free key-validation request warms the shared TLS connection; account information is not saved. Common input validation and credit-ledger bookkeeping are outside the timer. Total time includes decoding/detection, encoding, upload, provider response/parsing, and final temporary-file deletion. Capture, WorkManager scheduling, history persistence, text cleanup, and insertion are excluded.

`compare-recordings` keeps the same cumulative $5 credit ceiling and reserves conservatively before every call, but uses a 400-request per-session guard instead of the older codec experiment's 500-request cumulative guard. It imports prior reservations, never retries failed paid calls, and refuses an existing session ledger. Normal instrumentation skips both new comparison methods without their dedicated local/paid opt-in arguments.

On the Android 15 x86_64 debug emulator, direct original-M4A upload had a lower median than either shortened path on all 16 fixtures with unrestricted uploads. For the approximately 64-second source (34.85 seconds after trimming), six-run medians were original 0.590 s, shortened AAC/64 1.295 s, and shortened MP3/32 1.222 s. At the 1 Mbps upload limit they were 6.902 s, 3.691 s, and 2.702 s. The approximately 66-second source measured 0.694/1.495/1.360 s unrestricted and 7.197/5.151/3.250 s limited. For the 64-second example, decoding/detection added roughly 0.80 s unrestricted and encoding another 45–57 ms, exceeding the API-time saving; on the limited uplink, byte savings outweighed preparation.

The shortened paths beat original upload on three of the four limited-uplink fixtures. The remaining short no-speech fixture kept the original upload and added only detection overhead. The timers include all shortening-specific work. Word-edit agreement against original-M4A transcription was imperfect: 17 edits for AAC/64 and 7 for MP3/32 across 465 reference words in one sample per file. These differences include silence-removal effects and do not establish human-verified accuracy.

Metadata is saved as `recording-inputs.json`, `recording-plan-original-vs-trimmed.json`, `recording-results-original-vs-trimmed.json`, and `recording-summary-original-vs-trimmed.json` under `.gradle/codec-lab/`. This comparison reported $0.135761536828653060414; the cumulative ledger reached $0.316169618158549871644 across 812 successful paid requests. Collect metadata before `clean`, which also removes generated M4A fixture copies while retaining original MP3s and results.

### Production trimmed/compressed uploads

Enabling **Skip silence before transcription** now uses the bounded, overlapping decoder/Silero path for compressed recordings, then encodes shortened PCM as mono 16 kHz AAC-LC at 64 kbps in an M4A container. WAV recordings use the same speech decisions/padding and the same AAC encoder after trimming. This takes precedence over WAV compatibility mode for shortened uploads; WAV-only providers require Skip silence to be disabled. No-speech/no-removal cases retain the normal untrimmed upload path (including WAV conversion when requested), and originals remain intact for playback/history.

`AacEncoder` drains output before queueing more PCM to avoid input/output backpressure stalls. It pads the partial final frame and feeds three zero frames to flush delayed AAC audio before EOS. This can add up to approximately 256 ms of codec padding, but avoids dropping the final sound. A valid container and plausible duration alone are insufficient: test a sound confined to the final 20 ms. Cancellation is checked throughout encoding and immediately before the API call. Codec/muxer resources and temporary WAV/M4A files are released on success, failure, and cancellation; compression failures stop before a paid request and require explicit retry or disabling Skip silence. Compressed copies use the existing recovery-excluded `notedown-converted-` prefix.

Run `AacEncoderDeviceTest` and `SilenceFilterDeviceTest` on a device/emulator for synthetic ending-sound, malformed-input, failed-output, cancellation, no-speech, and disabled-setting checks. These use fakes and spend no API credits. An additional fake-API integration test accepts a runtime-only speech fixture at private `files/silence-upload/input.m4a`:

```sh
adb -s SERIAL shell am instrument -w -r \
  -e class 'com.notedown.AacEncoderDeviceTest#trimmedSpeechUploadsFinalizedAacAndCleansTemporaryFiles' \
  -e trimmedUploadFixture true \
  com.notedown.test/androidx.test.runner.AndroidJUnitRunner
```

Use a fixture with detectable speech and removable pauses. It verifies finalized AAC uploads at the expected bitrate/duration from M4A and WAV originals with either compatibility setting, unchanged original hashes, one request on API failure, cancellation during compression without an API call, and deletion of all prepared copies. Stage privately at runtime and remove the fixture afterward; never bundle recordings or transcripts in tests. Historical local VAD benchmark variants measure decoding/trimming alone; live `TranscriptionService` profiling now includes the production compression stage.
